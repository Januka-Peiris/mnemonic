# Fork Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Fork button at the end of an agent chat that opens a new chat tab in the same workspace carrying the full conversation.

**Architecture:** Add `fork_session` to the `AgentConnection` trait, sent as ACP `session/fork` by `AcpConnection`. Mnemonic's `ConversationView`s opt in to a Fork button in the thread footer, which emits an event; `WorkspaceView` forks the session, saves a new chat record with the forked session ID and opens it through the existing resume path (`open_chat`), which loads and replays the history.

**Tech Stack:** Rust, GPUI, `agent-client-protocol` 0.14 (`unstable` features already enabled, which includes `unstable_session_fork`).

**Spec:** `docs/superpowers/specs/2026-11-13-fork-chat-design.md`

## Global Constraints

- No `unwrap()`, no `let _ =` on fallible operations; log or propagate errors.
- No em dashes anywhere.
- The Fork button only appears in Mnemonic chats (`ConversationView::enable_fork`), never in Zed's own agent panel.
- The original chat's history is never changed.
- Run `cargo clippy -p <crate> --no-deps` per touched crate (the repo-wide `./script/clippy` has pre-existing failures); do not run `cargo fmt` on whole files (the repo is not fmt-clean).

## Review Focus

- Clicking Fork twice quickly: two forks, two tabs, both valid. Acceptable; no guard needed.
- The agent rejects the fork (old adapter, session gone): an error is shown via `workspace.show_error` and no record is written. Covered by Task 3's error path.
- Fork while the chat has no session yet (agent still connecting): button absent because the footer is only drawn for a thread with entries; `fork_chat` also returns early when `root_thread` is `None`.
- App restart after forking: the record holds the forked `acp_session_id`, so it resumes like any chat. Verified manually in Task 4.
- Agents without `session.fork` (Codex ACP, others): `supports_fork_session` is false, button hidden. Covered by Task 1's capability test.

### Task 1: `fork_session` on the agent connection

**Files:**
- Modify: `crates/acp_thread/src/connection.rs` (trait `AgentConnection`, beside `resume_session` ~line 138)
- Modify: `crates/agent_servers/src/acp.rs` (`impl AgentConnection for AcpConnection` beside `resume_session` ~line 1742; fake agent in `test_support::build_fake_acp_connection` ~line 2341; tests module)

**Interfaces:**
- Produces:
  - `fn supports_fork_session(&self) -> bool` (default `false`)
  - `fn fork_session(self: Rc<Self>, session_id: acp::SessionId, work_dirs: PathList, cx: &mut App) -> Task<Result<acp::SessionId>>` (default returns `Err("Forking sessions is not supported")`)
  - `AcpConnection::supports_fork_session` returns `self.agent_capabilities.session_capabilities.fork.is_some()`.
  - `AcpConnection::fork_session` converts `work_dirs` with `session_directories_from_work_dirs`, sends `acp::ForkSessionRequest::new(session_id, directories.cwd).additional_directories(..).mcp_servers(mcp_servers_for_project(..))` and returns `response.session_id`. It does not register a thread; the caller opens the new session with `load_session`/`resume_session`. Errors map through `map_acp_error`.

- [ ] **Step 1: Write the failing tests** in `acp.rs` tests, using `test_support::connect_fake_acp_connection`. Give the fake agent a `ForkSessionRequest` handler that responds `acp::ForkSessionResponse::new(acp::SessionId::new(format!("{}-fork", req.session_id)))`.
  - `fork_session_returns_the_agents_new_session_id`: set `session_capabilities.fork = Some(acp::SessionForkCapabilities::new())` via `Rc::get_mut` (as in `additional_directories_support_respects_agent_capability`); `fork_session(SessionId::new("original"), PathList::new(&[PathBuf::from("/a")]), cx)` resolves to `SessionId::new("original-fork")`; `supports_fork_session()` is true.
  - `fork_session_is_rejected_without_the_capability`: with `fork = None`, `supports_fork_session()` is false and `fork_session(..)` returns an error.
- [ ] **Step 2: Run** `cargo test -p agent_servers fork_session` and confirm both fail to compile (no `fork_session`).
- [ ] **Step 3: Implement** the trait methods and the `AcpConnection` impl above.
- [ ] **Step 4: Run** `cargo test -p agent_servers fork_session` and `cargo check -p acp_thread -p agent_servers`; expect PASS and no errors (other `AgentConnection` impls compile via the defaults).
- [ ] **Step 5: Commit** `Add session fork to agent connections`.

### Task 3: Fork the chat into a new tab

**Files:**
- Modify: `crates/mnemonic-panels/src/workspace_view.rs` (`build_chat` ~line 2622, `add_chat` ~line 2565, new `fork_chat` beside `add_chat`)

**Interfaces:**

- Produces: `fn fork_chat(&mut self, view_id: EntityId, window: &mut Window, cx: &mut Context<Self>)` and `fn forked_title(title: &str) -> String`.

- [ ] **Step 1: Write the failing test** `forked_chat_title_appends_fork` in the existing `#[cfg(test)]` module: `forked_title("Claude 2") == "Claude 2 (fork)"` and `forked_title("Claude 2 (fork)") == "Claude 2 (fork) (fork)"`.
- [ ] **Step 2: Run** `cargo test -p mnemonic-panels --lib forked_chat_title` and confirm it fails (no `forked_title`).
- [ ] **Step 3: Implement.**
  - Pull the work-dirs block out of `build_chat` into `fn chat_work_dirs(&self, cx: &App) -> Option<PathList>` and use it in both places.
  - In `build_chat`, call `view.enable_fork()` beside `suppress_notifications()`, and push `cx.subscribe_in(&view, window, move |this, _, event, window, cx| if let AcpServerViewEvent::ForkRequested = event { this.fork_chat(view_id, window, cx) })` into the chat's `_subscriptions`.
  - `fork_chat`: find the `ChatSession` whose `view.entity_id() == view_id`; take `view.read(cx).root_thread(cx)` (return if `None`); read its `session_id()` and `connection().clone()`; load the chat's record from `list_for_workspace` by `record_id` for its `agent` and `title`; call `connection.fork_session(session_id, work_dirs, cx)`; in `cx.spawn_in`, on `Ok(new_id)` build a `ChatSessionRecord` like `add_chat` does (new uuid, same `agent`, `title: forked_title(&original.title)`, `acp_session_id: Some(new_id.to_string())`, `is_review: false`, `is_primary: false`, `position: next_chat_position`), `insert` it and call `open_chat(record, None, window, cx)`. On `Err`, show it with the workspace's `show_error` and write nothing. Defer nothing extra: this runs from an event, outside any `WorkspaceHost` update.
